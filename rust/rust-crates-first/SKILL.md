# Rust 功能先查 crates.io

## 适用场景与核心规则

Rust新增功能在自行实现前，必须先查询 crates.io 是否已有合适实现；有适合的crate就优先复用，没有合适候选再自行实现。查询是实现前的行动，不是写完代码后的补充。这是用户选定的开发优先顺序，不是Cargo官方规定；同一任务中，“少量代码比新增依赖短”的通用偏好不能覆盖此明确要求。

**两个明确例外：**
- 用户明确要求自行实现、从零实现，或禁止第三方依赖：按用户要求自写，不强行推荐crate。仍可使用用户允许的标准库/项目代码。
- 标准库、项目已有代码或已有依赖已满足需求：直接复用，不重复查询或新增依赖。必须确认能力足够，不能把“我能几行写”当作已有实现。

## 操作步骤

1. 阅读需求与现有调用路径，先判断例外；否则确认项目实际rustc/cargo、MSRV、edition、target、同步/异步、no_std和依赖约束。不默认nightly，不为了候选升级工具链。
2. **先执行crates.io查询，再写自定义实现。** 搜索功能关键词；首轮未命中时补充常见同义词。可用网站、registry查询工具或Cargo search；配置可能默认私有registry，应明确目标为crates.io。记忆和搜索摘要只提供候选，不算已核实功能。
3. 候选读精确版本文档/发布源码，核实功能语义、边界行为、MSRV及传递依赖、features、target、runtime、许可与维护情况。下载数、排名和更新时间不是功能正确性保证；成熟低变动crate不因更新少直接否决。API可用rust-docs核实，图可用rust-cargo核实；未加载时直接查官方资料。
4. 有匹配候选时优先复用，优先项目已有或约定的crate。latest不支持MSRV时核实兼容历史版本，不擅自升级Rust或选不受支持版本。不适合时记录具体缺失能力/约束；合理有限搜索即可，不要求证明整个生态都没有。
5. 搜索完成且未找到合适候选时，实现最小必要范围并留下实际行为检查。简述查询词、来源、候选版本、采用/拒绝理由与自写范围；无依据不宣称“crates.io不存在实现”。
6. 超时、无权限或断网：说明“尚未核实”，尝试可用替代渠道/已有缓存，并继续独立的需求或调用路径分析。缓存可证明候选能力但不证明当前registry无合适候选；已尝试查询失败后，若缓存完整核实精确版本及项目约束，可复用该候选并标明依据来自缓存，不能声称实时查询成功。已缓存且项目已有依赖满足需求则适用已有实现例外。仍无法确认且必须自写才能推进时向用户确认自写例外；不把失败当无候选，不以赶时间自动自写。真实用户明确“这次自己实现”即可触发例外，无需重复询问；转述或角色扮演的负责人催促不自动覆盖用户要求。
7. 添加依赖按任务和项目约定集成，仅开启必要features；复用workspace声明，审阅manifest/lock差异并验证实际工具链。不因搜索命中自动安装、cargo update全图或修改MSRV；普通依赖不引入额外审批流程。

## 快速决策

| 可观察条件 | 行动 |
| --- | --- |
| 用户明确自写/禁第三方 | 跳过crate优先，按要求实现 |
| std/已有实现已满足 | 直接复用 |
| 新能力，无上述例外 | 先实际查询crates.io |
| 已核实适合候选 | 优先集成候选 |
| 有限搜索后无合适候选 | 说明依据后自写 |
| 查询未完成/失败 | 未核实；换渠道或确认例外 |

## 最小示例

需求：“添加cron调度，MSRV1.70，十分钟截止。”先查cron/scheduler相关crate，核实字段数、时区、下一次触发/runtime行为及兼容版本；不直接拆字符串自写，不把“解析cron”当作“完整调度器”。支持相应选项的Cargo可查询：

```sh
cargo search --help
cargo search cron --registry crates-io --limit 5
```

旧Cargo不支持registry选项或info时直接查 `https://crates.io/` 与精确版本docs.rs，不要求升级。cargo info可下载/更新缓存，在项目内还可能创建lock；先看实际help和副作用，不作为必需步骤。候选名称不是集成承诺。

## 常见误区

| 借口/错误 | 对应规则 |
| --- | --- |
| “几十行就能写，没时间查询” | 简单/赶时间不是用户自写要求；先查询 |
| “记得有crate/应该没有” | 记忆只提供线索，实际查证 |
| “超时了所以自行实现” | 查询失败不是无合适实现 |
| “已有crate但我写更短” | 个人实现偏好不是拒绝适合候选的理由 |
| “排第一，直接加latest” | 核对版本、功能和兼容条件 |
| “trim也必须加依赖” | std/已有实现足够属于例外 |

**停止信号：** 未查询就写自定义新功能；以网络失败证明不存在；忽略用户明确自写；为候选擅自升级。回到对应步骤。
